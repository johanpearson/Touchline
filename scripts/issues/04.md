## Goal
All user-facing text goes through i18n from day one.

## Acceptance criteria
- [ ] Typed message keys with English as source locale; Swedish locale
- [ ] `t(key, params)` with interpolation and plural support
- [ ] Locale switch in the UI, remembered between sessions (through a platform adapter, not direct `localStorage` in UI code)
- [ ] Test fails if a key exists in `en` but not in `sv` (or the other way round)
- [ ] Number and percent formatting per locale (`0.62` vs `0,62`)

## Notes
A small in-house solution is fine if it stays typed; otherwise a free library such as i18next. Justify the choice in the PR.
